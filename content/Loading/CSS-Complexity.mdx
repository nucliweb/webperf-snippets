# CSS complexity

Find what the CSS of the page carries that costs bytes and can go: images and fonts embedded as `data:` URLs, `@import` rules that delay the stylesheets they load, empty rules, repeated selectors, `@keyframes` that nothing uses and atypically complex selectors. The snippet reads every stylesheet of the page, including imported ones, adopted ones and those in shadow roots, and counts them the way [css-analyzer](https://github.com/projectwallace/css-analyzer) by Project Wallace does.

### Understanding the results

Each item is a stylesheet, the one with the most embedded bytes first:

- **source**: the URL of the stylesheet, or a label such as `<style> #1`, `adopted stylesheet #1` or `<style> in the shadow root of div#app`
- **read**: `cssom` when the page could read its rules, `fetched` for a stylesheet of another origin read with `fetch`, and `unreadable` when neither worked
- **ruleCount**, **embeddedBytes**, **importCount** and **importantCount**: its style rules, the size of its `data:` URLs, its `@import` rules and its `!important` declarations

`details` adds them up for the whole page:

- **stylesheetCount**, **fetchedCount** and **unreadableCount**: the stylesheets found, those read with `fetch`, and those that could not be read
- **ruleCount**, **selectorCount** and **declarationCount**: style rules (also nested and inside `@media` or `@supports`), selectors (each one of a list such as `.a, .b`) and declarations (also those of `@font-face` and `@keyframes`)
- **embeddedBytes**, **embeddedCount** and **embeddedTypes**: the size of all the `data:` URLs, in characters, how many there are, and both by MIME type, such as `font/woff2` or `image/svg+xml`
- **importCount** and **emptyRuleCount**: `@import` rules and style rules without declarations
- **selectorUniqueness**: unique selectors over all selectors, from 0 to 1. A selector repeated in two `@media` counts as repeated, as css-analyzer counts it
- **importantCount** and **importantPercent**: declarations with `!important`, and their share of all declarations
- **maxSelectorComplexity**, **commonSelectorComplexity** and **complexSelectors**: the complexity of the most complex selector, the most common one, and the 5 most complex selectors with theirs (see [Selector complexity](#selector-complexity))
- **fontFaceCount**, **keyframesCount** and **unusedKeyframes**: `@font-face` and `@keyframes` rules, and the names of the `@keyframes` that no `animation` or `animation-name` of the stylesheets or of a `style` attribute uses

### Stylesheets of another origin

The page cannot read the rules of a stylesheet of another origin loaded without `crossorigin` on its `<link>`. The snippet then requests it with `fetch`, which works when the server sends `Access-Control-Allow-Origin`, as many CDNs do, and parses it with the same CSSOM (`read: "fetched"`). It also follows the `@import` rules of that stylesheet. The request can come from the browser cache, and carries a `#webperf-snippets` fragment, so the snippets that list the resources of the page leave it out.

When `fetch` cannot read it either, the stylesheet is `unreadable`, `corsLimitedAnalysis` is `true` and the counts are a lower bound. Add `crossorigin` to the `<link>` and `Access-Control-Allow-Origin` to the server, or run the snippet on a page of that origin.

### Issues and thresholds

The thresholds come from [The CSS Selection 2026](https://www.projectwallace.com/the-css-selection/2026) by Project Wallace, which analyzed the CSS of about 100,000 homepages. They describe what real websites ship, not a budget: none of them is an error.

| Code | Severity | When |
| --- | --- | --- |
| `embedded-font` | warning | A stylesheet embeds a font as a `data:` URL. The font downloads with the stylesheet, blocks rendering with it and cannot be cached on its own |
| `embedded-content` | warning | The `data:` URLs of the page add up to more than 36.6 kB, more than [90% of homepages](https://www.projectwallace.com/the-css-selection/2026#stylesheet-composition) embed (the median is 2.23 kB) |
| `import` | warning | An `@import` rule: the browser only requests the imported stylesheet after it downloads and parses the one that imports it. [82% of homepages](https://www.projectwallace.com/the-css-selection/2026#at-rules) use none |
| `empty-rules` | info | Style rules without declarations |
| `duplicate-selectors` | info | Fewer than 66% of the selectors are unique, the threshold of [css-code-quality](https://github.com/projectwallace/css-code-quality) |
| `important-ratio` | info | More than 13% of the declarations use `!important`, more than on [90% of homepages](https://www.projectwallace.com/the-css-selection/2026#declarations) (the median is 2%) |
| `font-face-count` | info | More than 48 `@font-face` rules, more than on [90% of homepages](https://www.projectwallace.com/the-css-selection/2026#at-rules) (the median is 8). [Webfont usage analyzer](/Loading/Webfont-Usage-Analyzer) shows which load and which are never used |
| `unused-keyframes` | info | A `@keyframes` that nothing in the CSS or in a `style` attribute uses. It is not reported when a stylesheet could not be read, since that one could use it, and JavaScript can still set it later |
| `selector-complexity` | info | A selector with a complexity above 29, more than the most complex selector of [90% of homepages](https://www.projectwallace.com/the-css-selection/2026#selectors) (the median is 16) |
| `unreadable-stylesheets` | info | Stylesheets of another origin that neither the page nor `fetch` could read |

### Selector complexity

The complexity of a selector counts its parts, as [css-analyzer](https://github.com/projectwallace/css-analyzer) does: each type, class, id, attribute, pseudo-class, pseudo-element, combinator, `*` and `&` counts 1, and a vendor prefix or an attribute value 1 more. `:is()`, `:where()`, `:not()` and `:has()` add the selectors they hold, so `.nav > ul li:not(.active) a[href^="http"]` is 11.

Complexity says how hard a selector is to read and to maintain, not how long the browser takes to match it. To measure that cost, record a trace with **Enable CSS selector stats** in the Performance panel and open the [CSS selector costs](https://developer.chrome.com/docs/performance/insights/slow-css-selector) insight.

### What the CSSOM does not show

The snippet reads the CSS as the browser parsed it, not as it was written. The browser drops comments, hacks such as `*zoom`, invalid declarations and rules with a selector it does not support, writes a few shorthands as their longhands, rewrites values such as colors, and rewrites some selectors: `*::selection` becomes `::selection`, and a nested `.child` becomes `& .child`, which changes their complexity. The counts match those of the text when the CSS has none of them, and on the CSS of a production site they differ by about 1%. For the same reason the snippet does not give the size of the stylesheets: [Critical CSS detection](/Loading/Critical-CSS-Detection) gives the bytes of the CSS that blocks rendering, and [Compression audit](/Loading/Compression-Audit) the transfer size of each file.
